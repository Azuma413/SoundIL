# S2A2: Audio-Visual Imitation Learning for Manipulation Tasks Using Acoustic Spatial Information

S2A2 is a research codebase for studying imitation learning policies that use acoustic spatial cues in addition to visual observations. The project extends LeRobot-based policy training with simulated and real robot manipulation tasks in which sound can identify the relevant object, target, or task condition.

The core idea is to make acoustic information available to standard imitation learning policies such as ACT, Diffusion Policy, VQ-BeT, and Pi0. In simulation, sound propagation and microphone-array observations are generated with Pyroomacoustics and integrated into Genesis environments. Policies can then be trained and evaluated with the same LeRobot dataset and checkpoint structure used by the upstream training tools.

## What This Repository Contains

- Simulation environments for manipulation tasks with and without sound.
- Acoustic observation generation using microphone-array processing, sound maps, and spectrogram-like inputs.
- Dataset collection scripts that create LeRobot-format datasets from scripted expert behavior.
- Training entry points for ACT, Diffusion Policy, VQ-BeT, and Pi0.
- Evaluation utilities for simulated rollouts, real-robot Iloha experiments, and representation analysis with t-SNE.

## Requirements

The setup assumes:

- Ubuntu 24.04
- A CUDA-capable NVIDIA GPU
- `uv`
- System packages required by audio and video dependencies

Install the system packages first:

```bash
sudo apt update && sudo apt upgrade -y
sudo apt install portaudio19-dev ffmpeg -y
```

Clone the repository with submodules and install the Python environment:

```bash
git clone -b open --recurse-submodules https://github.com/Azuma413/SoundIL.git && cd SoundIL
uv sync
```
## Simulation Workflow

### Generate a Dataset

Simulation datasets are generated by scripted expert rollouts and saved under `datasets/` in LeRobot Dataset V3 format:

```bash
uv run src/s2a2/make_sim_dataset.py
```

Task names encode the manipulation and acoustic setting, for example `normal`, `sound`, `soundShake`, `soundDiff`, `soundAll`, and `soundSim` variants. The generated dataset directory name is later passed to training as `DATASET_NAME`.

### Train a Policy

Set the dataset name and choose one of the supported policies: `act`, `diffusion`, `vqbet`, or `pi0`.

```bash
export DATASET_NAME=<dataset-name>
export POLICY=act

uv run lerobot-train \
  --dataset.repo_id=local/${DATASET_NAME} \
  --dataset.root=datasets/${DATASET_NAME} \
  --policy.type=$POLICY \
  --output_dir=outputs/train/${POLICY}_${DATASET_NAME} \
  --job_name=${POLICY}_${DATASET_NAME} \
  --policy.device=cuda \
  --policy.push_to_hub=false \
  --wandb.enable=true \
  --wandb.disable_artifact=true \
  --batch_size=8 \
  --steps=100000
```

Training checkpoints are written to `outputs/train/<training-name>/checkpoints/`. For repeated experiments, it is useful to include the seed in the training name, for example `act_sound-m4-f10-s2-p0_0_seed0`.

### Evaluate a Checkpoint

`src/s2a2/eval_policy.py` loads a trained policy, reconstructs the matching Genesis task from the dataset or training name, and runs simulated evaluation episodes:

```bash
uv run src/s2a2/eval_policy.py \
  --training-name act_sound-m4-f10-s2-p0_0_seed0 \
  --dataset-name sound-m4-f10-s2-p0_0 \
  --checkpoint-step 100000 \
  --episode-num 100
```
## Representation Analysis With t-SNE

`src/s2a2/plot_tsne.py` evaluates a trained checkpoint, extracts hidden representations, and plots them with t-SNE. The `--color-by` option can be one of `sound_type`, `sound_coordinate`, or `success`. If it is omitted, all supported colorings are generated.

The `--hidden-reduction` option controls how temporal hidden states are converted into points:

- `auto`: select the model-specific current-step representation
- `none`: split hidden states by step and use each step as a point
- `first`: use the first hidden step
- `last`: use the last hidden step
- `mean`: average hidden states over the step dimension

```bash
uv run src/s2a2/plot_tsne.py \
  --training-name act_sound-m4-f10-s2-p0_0_seed0 \
  --checkpoint-step 100000 \
  --dataset-name sound-m4-f10-s2-p0_0 \
  --episode-num 100 \
  --hidden-reduction mean
```

## Real-Robot Workflow

Real-robot data collection and evaluation are built around the Iloha setup and a Meta Quest 3 controller interface.

### Data Collection

Install the Unity app from [KyotoVLATech/AlohaController](https://github.com/KyotoVLATech/AlohaController) on the Meta Quest 3, then start the server:

```bash
uv run src/s2a2/iloha_server.py
```

While the server is running, press the Connect button in the Quest app to connect the headset and PC. The robot can then be controlled with the Quest controllers.

### Evaluation

Example for the L&I task:

```bash
uv run src/s2a2/iloha_eval.py \
  --policy_path outputs/train/act_soundRealAll-m4-f10-s2-p0_seed0/checkpoints/200000/pretrained_model \
  --dataset_path datasets/soundRealAll-m4-f10-s2-p0 \
  --output_root datasets/eval \
  --episode_time_s 15 \
  --num_episodes 25 \
  --save_data \
  --sound_index 0 \
  --speaker right
```

Example for the exploratory task:

```bash
uv run src/s2a2/iloha_eval.py \
  --policy_path outputs/train/act_soundRealShake-m4-f10-s2-p0_seed0/checkpoints/200000/pretrained_model \
  --dataset_path datasets/soundRealShake-m4-f10-s2-p0 \
  --output_root datasets/eval \
  --episode_time_s 20 \
  --num_episodes 25 \
  --save_data \
  --is-sound-shake
```
